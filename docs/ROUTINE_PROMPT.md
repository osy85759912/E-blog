# 예약 트리거(Routine) 지시문

아래 내용을 `create_trigger`의 prompt로 사용한다. 매일 08:00 KST 실행 (9시 발행을 위해 검토 시간 확보).

---

E-blog 리포지토리(osy85759912/e-blog, 브랜치 claude/us-market-blog-automation-ke4cp6)의 자동화를 실행한다.

이 환경은 네트워크가 제한되어 있어 워드프레스 API나 주가 데이터에 직접 접근할 수 없다. 그래서 초안 작성까지만 하고, 실제 차트 생성·워드프레스 업로드는 GitHub Actions가 처리한다 (`.github/workflows/publish-draft.yml` 참고).

1. 웹 검색으로 지난 밤(미국 동부시간 기준 정규장~애프터마켓) 미국 증시 주요 이슈/가십을 조사한다. 단순 지수 등락이 아니라 화제성 있는 사건 하나를 고른다 (실적 쇼크, CEO 발언 논란, 급등락 종목, 소셜에서 화제된 종목 등).
2. `docs/style_guide.md`를 읽고 그 톤/구조/디스클레이머 규칙을 그대로 따라 글을 작성한다. 제목은 스타일 가이드의 클릭률 공식을 적용한다.
3. 이번 사건의 핵심 종목/섹터 티커 1~3개를 정한다.
4. `pending/<YYYY-MM-DD>.md` 파일을 아래 형식으로 작성한다:
   ```
   ---
   title: <제목>
   tickers: <티커1>,<티커2>
   ---
   <본문 HTML>
   ```
5. git add/commit/push 한다 (브랜치: claude/us-market-blog-automation-ke4cp6). 이 푸시가 GitHub Actions를 트리거해서 차트 생성 + 워드프레스 초안 업로드를 처리한다.
6. 푸시 직후, 사용자에게 푸시 알림을 보낸다: 글 제목, 한 줄 요약, "1~2분 후 워드프레스 관리자 페이지에 초안이 올라갑니다. 확인 후 발행 버튼을 눌러주세요"라는 안내. (Actions 완료를 기다리지 않고 바로 알림을 보낸다 — 실행 시간이 짧아 알림 확인 시점엔 대부분 이미 반영되어 있다.)
7. 매일 같은 종목/섹터가 반복되지 않도록, 전날 다룬 주제와 겹치면 다른 각도(다른 종목/다른 이슈)를 우선한다.

절대 하지 말 것:
- 검색으로 확인 안 된 수치·발언·인용을 지어내지 않는다.
- "매수/매도 추천" 같은 명시적 매매 지시 문구를 쓰지 않는다 (스타일 가이드의 의견 표현으로 대체).
- 이 환경에서 직접 워드프레스 API나 주가 API를 호출하려고 시도하지 않는다 (네트워크 차단으로 실패한다) — 반드시 `pending/`에 파일을 커밋하는 방식으로만 처리한다.
